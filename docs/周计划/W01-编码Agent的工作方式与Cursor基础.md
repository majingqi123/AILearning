# W01 周计划：编码 Agent 的工作方式与 Cursor 基础

- **所属阶段**：阶段一 AI 辅助编程（W1-W2）
- **起止日期**：（按主计划的示例是 2026-11-30 至 2026-12-06，以实际为准）
- **计划用时**：工作日 5 × 约 1.5 小时 + 周末约 3 小时，共约 10 小时

## 1. 本周目标

学完这一周，你应该能做到：

1. 讲清楚编码 Agent 是怎么工作的：模型、上下文窗口、工具调用、Agent 循环。
2. 会用 Ask、Plan、Agent 三种模式，知道各自什么时候用。
3. 会写规则文件和 `AGENTS.md`，让 AI 按你的约定干活。
4. 会管理上下文，会写出带验收标准的需求描述。
5. 知道 Rules、Skills、MCP 三者的区别，各用过一次。
6. 搭好 `labs/w01-topk` 的 C++ 工程骨架，为 W2 做准备。

### 周一：编码 Agent 是怎么工作的

**学习目标**

1. 理解模型是按概率预测文本的，同样的输入不保证同样的输出。
2. 理解上下文窗口是什么、里面装了什么。
3. 理解工具调用的过程，以及“Agent 就是循环里的工具调用”。

**时间安排**（约 85 分钟）

| 4 | 写笔记和自测 | 20 分钟 |

**学习资源**

**动手任务**

1. 在 Cursor 里向 Agent 提一个需要读文件才能回答的问题，例如“这个工作区的 `docs` 目录里有哪些文档，各讲什么”。
2. 展开它的每一步工具调用，记下：调用了哪些工具、顺序是什么、每一步拿到了什么。
3. 点输入框旁边的上下文占用环，看上下文被哪几类内容占用。
4. 画一张图：用户请求 → 模型 → 工具调用 → 工具结果 → 模型 → …… → 最终回答。

**验收标准**

- [ ] 能不看资料画出 Agent 循环图，并标出循环在什么条件下结束。
- [ ] 能说出一次对话的上下文里至少有哪 4 类内容。
- [ ] 能解释“读文件”这个动作是谁执行的。

**自测题**（写进当天的自我总结，闭卷回答）

1. 模型本身能读你硬盘上的文件吗？一次“读文件”从发起到拿到内容，经过了哪几步？
2. 上下文窗口里除了你的提问还有什么？为什么对话越长，效果可能越差？
3. 为什么同一句提示发两次，结果可能不一样？这对你使用 AI 写代码意味着什么？
4. 工具调用为什么会让 Token 消耗变多？

### 周二：三种模式与“先计划再执行”

**学习目标**

1. 知道 Ask、Plan、Agent 三种模式分别能做什么、不能做什么。
2. 掌握 Plan 模式的完整流程：澄清问题 → 出计划 → 改计划 → 执行。
3. 知道 Agent 做偏时怎么回退。

**时间安排**（约 85 分钟）

| 步骤 | 内容 | 时间 |
|---|---|---|
| 1 | 读资料 | 25 分钟 |
| 2 | 动手任务 | 40 分钟 |
| 3 | 写笔记和自测 | 20 分钟 |

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [Plan 模式](https://cursor.com/cn/docs/agent/plan-mode) | 见上方说明 | 必读 | 全文，很短 |
| [Ask 模式](https://cursor.com/cn/help/ai-features/ask-mode) | 见上方说明 | 必读 | 全文，很短 |
| [使用智能体编码的最佳实践](https://cursor.com/cn/blog/agent-best-practices) | 中文 | 必读 | “理解智能体 harness”和“从规划开始”两节 |
| [Cursor 智能体](https://cursor.com/cn/docs/agent/overview) | 中文 | 必读 | “Checkpoints”一节 |

**动手任务**

选一个小需求，例如“写一个 Python 脚本，统计指定目录下每个 Markdown 文件的字数和标题数，输出成表格”。放在 `labs/w01-scratch/` 里。

1. 用 Ask 模式问一个只读的问题，确认它不会改文件。
2. 切到 Plan 模式（输入框里按 `Shift+Tab`）提出需求，回答它的澄清问题。
3. 计划出来后手动改两处：删掉一个你认为多余的步骤，加一条约束（例如“只用标准库”）。
4. 执行计划，运行脚本确认结果。
5. 用 Checkpoint 回退到执行前，把计划改得更具体后再执行一次，比较两次结果。

**验收标准**

- [ ] 完整走过一次“计划 → 改计划 → 执行 → 回退 → 重做”。
- [ ] 能说出三种模式各自的适用场景，各举一个例子。
- [ ] 能说出什么样的任务不需要先计划。

**自测题**

1. Plan 模式比直接让 Agent 动手多了哪几步？这几步各自防止了什么问题？
2. Agent 做偏了，为什么“回到计划重来”常常比“追加提示修补”更好？
3. Checkpoint 和 git 有什么区别？各自该用在什么时候？

**动手任务**

**验收标准**

- [ ] `AGENTS.md` 和一条 `.mdc` 规则已存在。

- [ ] 能说出规则的四种应用方式。

**自测题**

1. 规则是怎么“生效”的？所以规则写得越长，代价是什么？
2. `alwaysApply`、`globs`、`description` 三个字段怎样决定一条规则何时被带上？
3. 哪些内容不该写进规则？为什么？
4. `AGENTS.md` 和 `.cursor/rules` 怎么选？

### 周四：上下文管理与提需求

**学习目标**

1. 知道什么时候手动引用文件，什么时候让 Agent 自己找。
2. 知道什么时候该开新对话。

**时间安排**（约 85 分钟）

| 1 | 读资料 | 25 分钟 |
| 2 | 动手任务 | 40 分钟 |
| 3 | 写笔记和自测 | 20 分钟 |

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [使用智能体编码的最佳实践](https://cursor.com/cn/blog/agent-best-practices) | 中文 | 必读 | “管理上下文”整节 |
| [给智能体写提示](https://cursor.com/cn/docs/agent/prompting) | 见上方说明 | 必读 | “@ mentions”和“Context usage”两节 |
| [@ 提及与上下文](https://cursor.com/cn/help/customization/context) | 见上方说明 | 选读 | 全文，很短 |

**需求描述的五个部分**（今天练习用）

| 部分 | 写什么 |
|---|---|
| 目标 | 要做成什么，一句话 |
| 背景 | 相关文件、已有约定、为什么要做 |
| 约束 | 语言标准、能用和不能用的库、性能或接口要求 |
| 验收标准 | 怎样算做完，最好是能运行的检查 |
| 不要做的事 | 不要改哪些文件、不要顺手重构 |

**动手任务**

1. 针对同一个需求写两份描述。需求是：“读取一个文本文件，每行是一个向量（空格分隔的浮点数），返回二维数组”。
   - 差的版本：一句话。
   - 好的版本：按上面五个部分写。
2. 开两个新对话分别执行，比较结果：错误处理、空行处理、接口设计、是否自带测试。
3. 在好的版本那个对话里继续追问几轮，观察上下文占用环的变化。
4. 练习一次用 `@` 引用文件，一次用 `@Chats` 引用之前的对话。

**验收标准**

- [ ] 笔记里有两份需求描述和结果对比。
- [ ] 能说出至少 3 种应该开新对话的情况。
- [ ] 有一份自己的需求描述模板。

**自测题**

1. 什么时候该 `@` 文件，什么时候该让 Agent 自己找？多引用无关文件有什么坏处？
2. 什么情况下开新对话，什么情况下继续当前对话？
3. 需求描述的五个部分里，你认为哪个最不能省？为什么？

- **只看不做**：这一周的内容看起来都懂，但差别在动手。每天的动手任务不要跳过。
- **规则写太多**：先写最少的几条，发现 AI 反复犯同一个错再加。
- **界面和文档对不上**：Cursor 更新很快，按钮位置可能和文档不同，以文档当前版本和实际界面为准。
- **在一个对话里做所有事**：换任务就开新对话，这本身就是周四要练的内容。
