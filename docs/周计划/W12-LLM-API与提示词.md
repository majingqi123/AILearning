## 1. 本周目标

学完这一周，你应该能做到：

1. 用 Python 调用 OpenAI 兼容接口，理解消息角色、Token 用量与计费字段。
2. 写出支持 SSE 流式输出、超时与重试的命令行聊天程序。
3. 会写并迭代系统提示、Few-shot、结构化输出；完成三版 C++ 代码审查提示词。
4. 实现多轮上下文的裁剪或摘要压缩。
5. 实现 Function Calling（查时间、读文件、算数），并用 C++ 复刻流式聊天 + 工具调用。

## 4. 每日安排

### 周一：API Key、请求结构、用量计费

**学习目标**

1. 跑通第一次 Chat Completions 调用。
2. 分清 `system` / `user` / `assistant`（以及后面的 `tool`）角色。
3. 会读响应里的 `usage`（prompt / completion tokens）。

**时间安排**：读文档 30 分钟，动手 40 分钟，笔记 20 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| 你所选服务商的 Chat API 文档 | 中/英 | 必读 | 鉴权、endpoint、messages、model |
| [OpenAI Chat Completions 参考](https://platform.openai.com/docs/api-reference/chat) | 英文 | 必读 | 字段含义（多数兼容服务对齐它） |
| [DeepSeek API 文档](https://api-docs.deepseek.com/zh-cn/) | 中文 | 选读 | 若用 DeepSeek |

**动手任务**

1. 用 `requests`/`httpx` 或官方 SDK 发一条非流式请求，打印回复与 `usage`。
2. 故意传错 Key / 错 model，记录错误码与信息，写进笔记（排错资产）。
3. 估算：按你服务商标价，1000 次“平均 1k prompt + 500 completion”大概多少钱。

**验收标准**

- [ ] 脚本稳定跑通。
- [ ] 能解释响应 JSON 里内容字段在哪。

**自测题**

1. 为什么要把 Key 放环境变量而不是写进代码？
2. `temperature` 对代码审查类任务通常该偏高还是偏低？
3. `usage` 里两类 Token 分别对应什么？

### 周二：流式输出、超时、重试

**学习目标**

1. 理解 SSE / 流式 chunk 的拼接方式。
2. 写出可用的命令行聊天循环。
3. 加上超时与有限次重试。

**时间安排**：读资料 20 分钟，动手 55 分钟，笔记 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| 服务商文档的 Streaming 章节 | 中/英 | 必读 | `stream=true` 与 chunk 格式 |
| [OpenAI Streaming 指南](https://platform.openai.com/docs/guides/streaming-responses) | 英文 | 选读 | 事件形态 |

**动手任务**

1. 实现流式打印：边收边显示，不攒完全文。
2. 做成 REPL：读入用户输入 → 流式输出 → 把 assistant 回复追加进历史。
3. 加：连接/读取超时；对 429/5xx 做指数退避重试（设最大次数）。
4. 模拟断网或故意短超时，确认程序不会裸崩溃。

**验收标准**

- [ ] 流式聊天可多轮使用。
- [ ] 超时与重试路径有日志可观察。

**自测题**

1. 流式模式下，最终 `usage` 常见在什么时机出现？
2. 为什么重试要对“写文件”类工具特别小心？
3. 用户 Ctrl+C 时你应该取消什么？

### 周三：系统提示、Few-shot、结构化输出

**学习目标**

1. 会写清晰的系统提示（角色、规则、输出格式）。
2. 会用 Few-shot 约束风格。
3. 会要求 JSON / JSON Schema 式结构化输出，并做校验。

**时间安排**：读资料 25 分钟，写提示词与迭代 50 分钟，笔记 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [OpenAI Prompt Engineering 指南](https://platform.openai.com/docs/guides/prompt-engineering) | 英文 | 必读 | 清晰指令、示例、格式 |
| 服务商的 Structured Outputs / JSON Mode 文档 | 中/英 | 必读 | 有则用官方约束 |
| [DeepSeek 提示词相关说明](https://api-docs.deepseek.com/zh-cn/) | 中文 | 选读 | 若用 DeepSeek |

**动手任务**

1. 任务：C++ 代码审查助手。输出固定字段，例如：`summary`、`issues[]`（含 severity/location/reason/suggestion）、`safe_to_merge`。
2. 写三版提示词：
   - v1：短系统提示
   - v2：加入 Few-shot（1–2 个审查样例）
   - v3：强化结构化约束 + 边界（不编造看不到的代码、不确定就标 uncertain）
3. 用同一段有意埋坑的 C++ 代码测三版，做对比表：格式服从、漏报/误报、稳定性。
4. 对模型输出做 JSON 解析；失败则重试或降级提示。

**验收标准**

- [ ] 三版提示词与对比表都在 `prompts/`。
- [ ] 至少一版能稳定产出可解析 JSON。

**自测题**

1. Few-shot 示例太偏会怎样？
2. 为什么结构化输出还要在程序侧校验？
3. 系统提示和用户提示的分工你怎么划分？

### 周四：多轮上下文管理

**学习目标**

1. 理解上下文窗口是硬约束。
2. 实现至少一种历史管理策略：裁剪或摘要压缩。
3. 建立“上下文工程”意识：塞什么、不塞什么、按什么顺序。

**时间安排**：读资料 20 分钟，动手 55 分钟，笔记 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| 服务商关于 context length / token 限制的说明 | 中/英 | 必读 | 上限与报错 |
| [Anthropic：上下文工程相关文章](https://www.anthropic.com/engineering) | 英文 | 选读 | 检索其 context 工程讨论，建立思路 |

**动手任务**

1. 给聊天程序加 Token 预算（可用粗估：字符数/4，或用 tiktoken/服务商 tokenizer）。
2. 实现策略 A：保留 system + 最近 K 轮；更早的丢掉。
3. 实现策略 B（可选其一即可深度做）：超长时把旧历史摘要成一条 system/user 笔记再继续。
4. 造一个“很长的对话”测试：确认不会动不动 400 上下文溢出。

**验收标准**

- [ ] 长对话下程序仍能继续聊。
- [ ] 笔记写清你选的策略及取舍。

**自测题**

1. 只保留最近 K 轮可能丢什么重要信息？
2. 摘要压缩可能引入什么错误？
3. 工具调用结果是否应该全文长期留在历史里？

### 周五：Function Calling

**学习目标**

1. 理解工具调用闭环：模型提出调用 → 程序执行 → 结果回传 → 模型继续生成。
2. 实现三个工具：查时间、读文件、算数。
3. 会做参数校验与多工具串行。

**时间安排**：读文档 25 分钟，动手 55 分钟，笔记 10 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| 服务商 Function Calling / Tools 文档 | 中/英 | 必读 | tools 定义、tool_calls、role=tool |
| [OpenAI Function Calling 指南](https://platform.openai.com/docs/guides/function-calling) | 英文 | 必读 | 循环与并行工具概念 |

**动手任务**

1. 用 JSON Schema 定义三个 tool。
2. 写执行器：校验参数 → 执行 → 返回字符串/JSON 结果。
3. 读文件工具必须限制在工作目录内（路径穿越直接拒绝）。
4. 写演示对话：需要组合工具才能答对的问题（例如“读取某文件里的数字并计算”）。
5. 设 `max_tool_steps`，防止死循环。

**验收标准**

- [ ] 三工具均可被正确触发与回传。
- [ ] 能向别人讲清“模型不会真的执行工具”。

**自测题**

1. 为什么要对工具参数做 schema 校验？
2. 工具结果是角色 `tool` 还是继续当 `user`？以你用的 API 为准。
3. 并行 tool_calls 时，回传顺序要注意什么？

## 7. 容易踩的坑

- **Key 泄露**：截图、日志、误提交 `.env`。
- **把流式当非流式解析**：chunk 拼错会得到乱码或半截 JSON。
- **工具无沙箱**：读文件不校验路径非常危险。
- **提示词一次写很长却不评测**：必须同题对比三版。
- **C++ 周末范围膨胀**：先跑通再加美观与多工具。
