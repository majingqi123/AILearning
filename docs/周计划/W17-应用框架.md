- **所属阶段**：阶段五 AI 应用开发（W12-W18）

- **计划用时**：工作日 5 × 约 1.5 小时 + 周末约 3 小时，共约 10–11 小时

## 1. 本周目标

学完这一周，你应该能做到：

1. 掌握 LangGraph 的 State、Node、Edge、条件边、Checkpoint。
2. 用 LangGraph 重写 W15 编码 Agent，功能对齐手写版。
3. 对比手写版与框架版的代码量、可控性、调试难度。
4. 说清 LangChain、LlamaIndex、Dify、AutoGen 各自适合什么场景。
5. 形成自己的“什么时候用框架、用哪个”决策笔记。

## 4. 每日安排

### 周一：LangGraph 核心概念

**学习目标**

1. 理解把 Agent 建模为图：状态在节点间流转。
2. 跑通官方入门示例，会用条件边与 checkpoint。

**时间安排**：读文档 40 分钟，跟写示例 35 分钟，笔记 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [LangGraph 文档](https://langchain-ai.github.io/langgraph/) | 英文 | 必读 | 快速开始、Graph API |
| Persistence / Checkpoint 文档页 | 英文 | 必读 | 状态恢复 |
| W15 状态设计笔记 | — | 必读 | 对照 State 该放什么 |

**动手任务**

1. 跟官方示例跑通一个最小图（不必是编码 Agent）。
2. 自己改一版：给 State 加字段，加一个条件边分支。
3. 启用 checkpoint，演示中断后恢复。
4. 笔记用自己的话定义：State / Node / Edge / 条件边 / Checkpoint。

**验收标准**

- [ ] 入门示例可运行。
- [ ] 能画出该示例的状态转移图。

**自测题**

1. LangGraph 的 State 为什么通常用可合并的结构？
2. 条件边和让模型“随便说下一步”有何不同？
3. Checkpoint 与 W15 自己存 JSON 是什么关系？

### 周二：用 LangGraph 重写编码 Agent（上）

**学习目标**

1. 把 W15 工具与主循环映射到 Graph 节点。
2. 先打通：模型决策 → 工具执行 → 回到模型。

**时间安排**：设计 25 分钟，编码 50 分钟，笔记 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| LangGraph Tool Calling / Agent 示例 | 英文 | 必读 | 官方推荐写法 |
| W15 `tools/` | — | 必读 | 复用工具函数 |

**动手任务**

1. 定义 `CodeAgentState`：messages、workspace、build_result、step_count 等。
2. 节点建议：`call_model`、`run_tools`、`should_continue`（条件）。
3. 先只支持 `read_file` / `write_file` / `build` 三件套。
4. 跑一个已知编译错误样本，看图能否进入修错循环。

**验收标准**

- [ ] 图能循环调用工具。
- [ ] `max_steps` 有等价限制（步数或节点访问次数）。

**自测题**

1. 工具节点失败时，错误如何写回 State？
2. 消息历史放在 State 的哪里？
3. 为什么先瘦身工具集再追求功能完备？

### 周三：重写编码 Agent（下）

**学习目标**

1. 补齐与 W15 对齐的关键能力：日志轨迹、HITL（可简化）、修到编译通过。
2. 达到可演示。

**时间安排**：编码 70 分钟，验收 20 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| LangGraph Human-in-the-loop 文档 | 英文 | 必读 | interrupt / 审批模式（有则用） |
| W15 三类错误样例 | — | 必读 | 回归输入 |

**动手任务**

1. 加轨迹打印或把 trace 写入 State/文件。
2. （可选但推荐）对 `write_file` 做确认中断。
3. 用 W15 的 3 类编译错误回归；目标：框架版也能修过。
4. README 写清：如何指定 workspace、如何恢复 checkpoint。

**验收标准**

- [ ] LangGraph 版在同样样例上能修到编译通过。
- [ ] 与手写版功能清单对照，差异写明。

**自测题**

1. 框架帮你省掉了哪些样板代码？
2. 哪些逻辑仍然必须自己写？
3. 调试时你是看图可视化，还是看 trace 更有效？

## 7. 容易踩的坑

- **被框架带着绕远路**：Agent 行为对不齐时，回到 W15 规格对照。
- **周五周六变成文档旅行**：横向了解要有输出（表格/选型），不是只收藏链接。
- **Dify 体验后全盘否定手写**：低代码适合产品化演示，不等于理解原理。
- **依赖升级导致 API 对不上**：以你安装当日的官方文档为准，笔记里记下版本。
- **时间不够**：主计划允许裁剪横向了解，但 LangGraph 重写不要砍。
