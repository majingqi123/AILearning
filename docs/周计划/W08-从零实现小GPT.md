## 1. 本周目标

学完这一周，你应该能做到：

1. 跟完 Karpathy 的 “Let's build GPT”，自己敲出一份能训练的字符级 GPT。
2. 讲清从 bigram 基线到完整 Transformer 块之间每一步加了什么。
3. 会看损失曲线，会调温度等采样参数生成文本。
4. 通过改层数、头数、上下文长度，说出超参数对效果和显存的影响。
5. 完成阶段三检查点：不看资料能画出 Transformer 前向过程。

## 4. 每日安排

### 周一：数据、字符级分词、bigram 基线

**学习目标**

1. 完成字符级词表、编码 / 解码。
2. 会构造语言模型的输入 `x` 和目标 `y`（下一个字符）。
3. 实现并训练一个 bigram 基线，建立“先有基线再加结构”的习惯。

**时间安排**：看视频对应部分 40 分钟，动手 40 分钟，笔记和自测 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [Let's build GPT（YouTube）](https://www.youtube.com/watch?v=kCc8FmEb1nY) | 英文 | 必读 | 开头到 bigram 模型训完、能采样 |
| [ng-video-lecture](https://github.com/karpathy/ng-video-lecture) | 英文代码 | 必读 | 对照 `bigram.py` |
| [Happy-LLM 第五章相关准备](https://datawhalechina.github.io/happy-llm/) | 中文 | 选读 | 若需要中文术语对照 |

**动手任务**

1. 下载语料，统计字符词表大小，实现 `encode` / `decode`。
2. 按 `block_size`（上下文长度）从语料切出训练 batch：输入是一段字符，目标是向右错一位。
3. 实现 bigram 模型：本质是一个 `nn.Embedding`，用当前字符预测下一个。
4. 训练若干步，画出损失下降；采样一段文字（会很乱，这是正常的）。

**验收标准**

- [ ] 能正确编解码往返。
- [ ] bigram 训练损失下降。
- [ ] 能采样出一段（尽管不通顺的）文本。

**自测题**

1. 语言模型的训练样本 `(x, y)` 是怎么从原文构造的？
2. bigram 只用了什么信息预测下一个字符？它的上限大概在哪？
3. `block_size` 和 batch 里的序列长度是什么关系？

### 周二：自注意力

**学习目标**

1. 在语言模型设定下实现自注意力（带因果掩码）。
2. 看懂注意力权重如何让“当前字符”聚合前面的信息。

**时间安排**：看视频 40 分钟，动手 40 分钟，笔记和自测 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [Let's build GPT](https://www.youtube.com/watch?v=kCc8FmEb1nY) | 英文 | 必读 | 自注意力实现那一段 |
| [W07 自己的注意力笔记和代码](W07-序列建模注意力与Transformer.md) | 中文 | 必读 | 复习 QKV 与掩码 |

**动手任务**

1. 把单头自注意力接到模型里：从 token 表示生成 Q、K、V，做缩放点积，加因果掩码，加权求和。
2. 可视化某一个位置的注意力权重（对前面位置的分布）。
3. 对比：只有 Embedding 的 bigram，和加了单头注意力之后的损失（同样训练步数）。

**验收标准**

- [ ] 因果掩码正确（未来位置权重为 0）。
- [ ] 单头注意力版本损失低于纯 bigram。
- [ ] 有一张注意力权重可视化图。

**自测题**

1. 在字符级 GPT 里，Q、K、V 是从哪里来的？
2. 为什么这里必须用因果掩码？
3. 单头注意力相对 bigram，多利用了什么信息？

### 周三：多头注意力与前馈层

**学习目标**

1. 把单头扩展成多头，再投影回去。
2. 加上位置级的前馈网络（MLP）。
3. 理解“注意力做通信，前馈做计算”的分工直觉。

**时间安排**：看视频 40 分钟，动手 40 分钟，笔记和自测 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [Let's build GPT](https://www.youtube.com/watch?v=kCc8FmEb1nY) | 英文 | 必读 | Multi-Head 与 FeedForward 部分 |
| [动手学深度学习：多头注意力](https://zh.d2l.ai/chapter_attention-mechanisms/multihead-attention.html) | 中文 | 选读 | 对照实现细节 |

**动手任务**

1. 实现 `MultiHeadAttention`：多个头并行，拼接后线性层。
2. 实现 `FeedForward`：两层线性，中间 ReLU 或 GELU，维度通常是 `4 * n_embd`。
3. 把两者串进一个 Block 的雏形（残差和 LayerNorm 可以留到周四）。
4. 打印训练中的参数量，确认多头后参数增加合理。

**验收标准**

- [ ] 多头 + 前馈的模型能训练，损失继续下降。
- [ ] 代码里每一步都有形状注释。

**自测题**

1. 多头拼接之后为什么还要乘一个输出投影矩阵？
2. 前馈网络是作用在序列长度维度上，还是特征维度上？
3. `n_head` 不能整除 `n_embd` 会怎样？

### 周四：残差、LayerNorm、Dropout，组成完整 GPT

**学习目标**

1. 按 Pre-LN 或视频中的结构，拼出完整 Transformer Block。
2. 堆叠多层，加上 token embedding 与 position embedding。
3. 得到一个可训练的迷你 GPT。

**时间安排**：看视频 40 分钟，动手 45 分钟，笔记和自测 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [Let's build GPT](https://www.youtube.com/watch?v=kCc8FmEb1nY) | 英文 | 必读 | Block、完整模型、生成循环 |
| [nanoGPT](https://github.com/karpathy/nanoGPT) | 英文代码 | 选读 | `model.py` 对照结构，不要整文件抄 |

**动手任务**

1. 给注意力和前馈都加上残差连接与 LayerNorm、Dropout。
2. 堆叠 `n_layer` 个 Block；加入 token embedding、position embedding、最终 LayerNorm 与线性输出头。
3. 实现 `generate`：逐步取最后一个位置的 logits，采样下一个 token，拼回序列。
4. 端到端跑通：训练几百到几千 step，能生成比 bigram 更像英文单词的片段。

**验收标准**

- [ ] 完整模型能训练至损失明显低于 bigram。
- [ ] `generate` 能产出可读性好于乱码的文本。
- [ ] 代码整理成清晰模块（或单文件但分区明确）。

**自测题**

1. 残差连接在深层 GPT 里主要防止什么问题？
2. token embedding 和 position embedding 通常如何合并？
3. 生成时为什么每次只关心最后一个位置的 logits？

### 周五：训练、观测、采样参数

**学习目标**

1. 认真跑一次训练，记录曲线和样例。
2. 理解 temperature、top-k 对生成的影响。
3. 初步估计显存 / 耗时与模型规模的关系。

**时间安排**：训练与调参 60 分钟，整理日志 15 分钟，笔记和自测 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [Let's build GPT](https://www.youtube.com/watch?v=kCc8FmEb1nY) | 英文 | 必读 | 训练建议与生成部分 |
| [LLMs-from-scratch](https://github.com/rasbt/LLMs-from-scratch) | 英文 | 选读 | 采样相关章节，作对照 |

**动手任务**

1. 固定一套默认超参，完整训练一版，保存 checkpoint。
2. 记录：最终 train/val loss、参数量、tokens/s、显存占用（或 CPU 耗时）。
3. 同一 prompt 下对比 `temperature=0.2 / 0.8 / 1.2` 的生成结果。
4. （可选）实现简单 top-k 采样，对比有无 top-k。

**验收标准**

- [ ] 有一份可复现的训练日志。
- [ ] 有不同 temperature 的样例对比。
- [ ] checkpoint 能重新加载并继续生成。

**自测题**

1. temperature 变大时，采样分布会发生什么变化？
2. 为什么要看 validation loss，而不是只看 training loss？
3. 上下文长度加倍，大致如何影响计算量和显存？

## 7. 容易踩的坑

- **直接复制最终文件**：失去本周意义。按天跟视频写。
- **一上来把模型做很大**：先小配置跑通，再放大。
- **没做因果掩码**：训练好像能跑，生成会“作弊”，验证时表现异常。
- **只看训练 loss**：过拟合时 val loss 会抬头，生成也会变差。
- **本周超时**：视频长、实现密，不够就动用缓冲周，不要夹生进入 W9。
