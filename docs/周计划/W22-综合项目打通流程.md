## 1. 本周目标

学完这一周，你应该能做到：

1. 写清综合项目设计文档：目标、架构、工具集、验收标准。
2. 为选定图形库（默认 raylib）建好可检索知识库（头文件函数切分 + 示例 + 常用做法备忘）。
3. 用 20 个“怎么做某事”问题测检索命中率并调整切分。
4. 打通：需求 → 检索 → 生成 `main.cpp` → 写入 CMake 模板工程。
5. 打通编译修复循环，并在周末让 3–5 条简单需求能编译运行。

## 4. 每日安排

### 周一：设计文档与模板工程

**学习目标**

1. 把综合项目边界写死，避免周末范围爆炸。
2. 准备可被 Agent 写入的 CMake 模板工程。

**时间安排**：设计 50 分钟，模板工程 40 分钟，笔记 10 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [raylib](https://www.raylib.com/) / [cheatsheet](https://www.raylib.com/cheatsheet/cheatsheet.html) | 英文 | 必读 | API 体量与示例风格 |
| W15/W17 Agent 设计 | — | 必读 | 工具与循环 |
| 主计划阶段七说明 | 中文 | 必读 | 验收标准 |

**动手任务**

1. 写 `DESIGN.md`，至少包含：
   - 目标与非目标（例如：不做完整 IDE、不做任意仓库级重构）
   - 架构图：Retriever / Generator / Builder / Repair Agent / Runner
   - 工具集与权限
   - 成功标准（本周：3–5 条简单需求编译运行）
   - 风险与裁剪顺序
2. 建 `template/`：CMake + 空白/最小 `main.cpp` + 链上 raylib 的说明。
3. 手工编译运行一次模板，确保基线绿色。

**验收标准**

- [ ] `DESIGN.md` 可给别人讲 10 分钟。
- [ ] 模板工程可编译运行。

**自测题**

1. 为什么要先写非目标？
2. 生成代码写入模板，比从零生成整个构建系统更稳在哪？
3. 本周与 W23 的分工是什么？

### 周二：建知识库

**学习目标**

1. 把头文件按函数切分入库，示例按文件入库。
2. 加一份“常用做法备忘”（窗口、主循环、相机、输入、基础 3D 等）。
3. 建混合检索索引。

**时间安排**：切分与入库 70 分钟，备忘 20 分钟，笔记 10 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| W14 代码切分与混合检索 | — | 必读 | 直接复用 |
| raylib 头文件与 examples | C | 必读 | 语料 |
| raylib cheatsheet | 英文 | 必读 | 备忘素材 |

**动手任务**

1. 索引范围写进配置：哪些目录纳入、哪些排除。
2. chunk metadata：`path`、`symbol`、`kind`、`lines`、`source_type`（api/example/note）。
3. 手写 `kb/notes/cookbook.md`：10–20 条高频模式，带最短代码骨架。
4. 跑通 `index` 命令，抽样检查 `InitWindow`、`BeginDrawing`、基础 3D 示例是否在库中。

**验收标准**

- [ ] 知识库可检索且含 API + 示例 + 备忘三类来源。
- [ ] 配置与重建步骤写入 README。

**自测题**

1. 为什么示例文件往往比头文件声明更有用？
2. cookbook 和原始代码谁作答时更该优先引用？
3. 索引过期了会发生什么？

### 周三：用 20 题测检索并调切分

**学习目标**

1. 建 20 个“怎么做某事”检索题。
2. 根据命中率回调切分/混合检索参数。

**时间安排**：出题 30 分钟，评测 40 分钟，调参 30 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| W14 评测脚本 | — | 必读 | 复用指标 |
| raylib examples 目录 | C | 必读 | 出题灵感 |

**动手任务**

1. 题例：创建窗口、读键盘、画旋转立方体、FPS 相机、加载模型、播声音、2D 相机、碰撞……覆盖易/中。
2. 每题标注期望 `symbol` 或 example 路径。
3. 报 Recall@K / MRR；对失败题改切分、补 cookbook、调 α/重排。
4. 输出 `eval/retrieval.md`：基线 → 调整 → 第二轮数据。

**验收标准**

- [ ] 20 题与两轮检索数据齐全。
- [ ] 命中率达到你在 DESIGN 里写的阈值（建议先定可实现的数，如 Recall@5 ≥ 0.7）。

**自测题**

1. 检索差却继续做生成，后果是什么？
2. 为什么调参要留对照表？
3. 中文需求如何改写成更利于检索的 query？

### 周四：生成流程

**学习目标**

1. 实现：需求 → 检索 → 拼提示词 → 生成 `main.cpp` → 写入模板工程。
2. 生成提示词强制：优先使用检索到的 API，不编造不存在的函数。

**时间安排**：提示词 30 分钟，编码 55 分钟，试跑 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| W12 结构化输出与提示词迭代 | — | 必读 | — |
| W13/W14 RAG 提示词 | — | 必读 | 忠实于资料 |

**动手任务**

1. Pipeline 输入：自然语言需求；输出：覆盖 `template/src/main.cpp`（路径以你设计为准）。
2. Prompt 中明确：主循环结构、资源释放、错误时的注释假设。
3. 先手工选 3 条简单需求看生成质量（先不要求必过编译）。
4. 保存每次生成的检索上下文与模型输出，便于周五修错。

**验收标准**

- [ ] 一键生成并写入工程。
- [ ] 生成物至少“看起来像”可编译的 raylib 程序。

**自测题**

1. 为什么要把检索片段原文塞进提示词？
2. 生成多文件 vs 单 `main.cpp`，本周如何选择？
3. 如何减少模型调用不存在的 API？

---

### 周五：编译修复循环

**学习目标**

1. 接上 build / 读错误 / 带上下文修复 / 最大轮数。
2. 修到编译通过（运行验证可放到周末细化）。

**时间安排**：接线 40 分钟，修错联调 55 分钟，笔记 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| W15 编码 Agent 工具与轨迹 | — | 必读 | 直接复用 |
| W18 安全约束 | — | 必读 | 沙箱与 HITL |

**动手任务**

1. 循环：`build` → 解析 error → `read_file`/`search_kb` → `write_file` → 再 build。
2. `max_repair_rounds`（例如 5）；失败则输出最后错误与轨迹。
3. 用周四的失败生成样例练到至少 2 条能编译通过。
4. 日志：每轮改动摘要、是否命中知识库。

**验收标准**

- [ ] 修复循环可自动跑。
- [ ] 至少 2 条需求从失败修到编译通过。

**自测题**

1. 为什么修复时还要再检索知识库？
2. 最大轮数太小/太大各有什么问题？
3. 哪些修复动作需要 HITL？
