## 1. 本周目标

学完这一周，你应该能做到：

1. 实现混合检索（BM25 + 向量），并会用元数据过滤 / 相似度阈值。
2. 加入 Cross-Encoder 重排，能量化重排前后差异。
3. 实现 Query Rewrite，并理解多路检索、父文档、压缩、Graph RAG 的思路。
4. 用 tree-sitter（或等价方案）按函数/类切 C++ 代码并保留签名与路径。
5. 建 20 题测试集，算召回/MRR/忠实度；做出可复用的 raylib（或选定库）代码问答工具。

## 4. 每日安排

### 周一：混合检索、过滤与阈值

**学习目标**

1. 理解关键词检索与向量检索的互补。
2. 实现 BM25 + 向量的融合（简单分数归一化后加权即可）。
3. 会做元数据过滤与相似度阈值。

**时间安排**：读资料 25 分钟，动手 50 分钟，笔记 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [All-in-RAG：进阶检索](https://github.com/datawhalechina/all-in-rag) | 中文 | 必读 | 混合检索相关章节 |
| [BM25 概念速览（任意可靠博客/wiki）](https://en.wikipedia.org/wiki/Okapi_BM25) | 英文 | 必读 | 公式直觉：词频、文档长度、IDF |
| W13 纯向量基线 | — | 必读 | 作为对照组 |

**动手任务**

1. 对同一语料建 BM25 索引与向量索引。
2. 融合策略：例如两边各取 Top-N，分数 min-max 归一化后 `α*vec + (1-α)*bm25`。
3. 加：按路径前缀/语言/标题过滤；丢弃相似度低于阈值的结果。
4. 选 10 个问题对比纯向量 vs 混合：命中率与主观质量。

**验收标准**

- [ ] 有对比表与结论（混合是否真的更好、在哪类问题上更好）。
- [ ] 过滤与阈值可配置。

**自测题**

1. 什么问题上 BM25 往往强过向量？
2. 分数不归一化直接加会怎样？
3. 阈值过高过低的症状各是什么？

### 周二：重排（Rerank）

**学习目标**

1. 分清 Bi-Encoder（Embedding）与 Cross-Encoder（重排）的计算差异。
2. 在候选集上加重排，对比前后。

**时间安排**：读资料 25 分钟，动手 50 分钟，笔记 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [Sentence Transformers：Retrieve & Rerank](https://www.sbert.net/examples/applications/retrieve_rerank/README.html) | 英文 | 必读 | 两阶段模式 |
| 所选 reranker 模型卡 | 中/英 | 必读 | 输入格式与分数含义 |
| [All-in-RAG](https://github.com/datawhalechina/all-in-rag) | 中文 | 选读 | 重排章节 |

**动手任务**

1. 召回阶段取 Top-30，重排后取 Top-5 喂给 LLM。
2. 记录耗时：召回 vs 重排 vs 生成。
3. 同一测试题对比：无重排 / 有重排的答案质量与“正确答案是否进入 Top-5”。
4. 写清：为什么不能对全库直接上 Cross-Encoder。

**验收标准**

- [ ] 有重排前后对比数据。
- [ ] 能解释 Bi-Encoder / Cross-Encoder 的速度与精度权衡。

**自测题**

1. Cross-Encoder 为什么通常更准也更慢？
2. 召回 K 太小导致重排也无法挽回，这叫什么问题？
3. 重排分数能否跨 query 绝对比较？

### 周三：Query Rewrite 与进阶检索思路

**学习目标**

1. 实现 Query Rewrite（把口语问题改写成更利于检索的查询）。
2. 概念层面掌握：多路检索、父文档检索、上下文压缩、Graph RAG。

**时间安排**：读资料 35 分钟，动手 40 分钟，笔记 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [All-in-RAG 进阶策略](https://github.com/datawhalechina/all-in-rag) | 中文 | 必读 | Query 改写、多路、压缩等 |
| [Microsoft GraphRAG 概念介绍](https://microsoft.github.io/graphrag/) | 英文 | 选读 | 只了解思路，不要求实现 |
| W12 LLM API | — | 必读 | 用 LLM 做改写 |

**动手任务**

1. 实现：`user_query → LLM 改写 → 检索`；保留原 query 与改写 query 的多路召回再合并。
2. 对比 8–10 道“措辞与文档用词不一致”的题。
3. 笔记各用 3–5 句话说明：父文档检索、上下文压缩、Graph RAG 解决什么、代价是什么。
4. （可选）实现一个极简上下文压缩：让 LLM 把 Top-K 片段压成要点再生成。

**验收标准**

- [ ] Query Rewrite 可开关，有前后对比。
- [ ] 进阶概念笔记完成（实现不做全套）。

**自测题**

1. 改写过度会引入什么风险？
2. 父文档检索为什么能缓解“片段碎片化”？
3. Graph RAG 更适合哪类问题？

### 周四：面向代码的切分

**学习目标**

1. 按函数 / 类切 C++，而不是按固定字符硬切。
2. 保留：签名、文档注释、文件路径、起止行号。

**时间安排**：读资料 25 分钟，动手 55 分钟，笔记 10 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [tree-sitter 官网](https://tree-sitter.github.io/tree-sitter/) | 英文 | 必读 | 解析与遍历 |
| [tree-sitter-cpp](https://github.com/tree-sitter/tree-sitter-cpp) | 英文 | 必读 | C++ grammar |
| raylib 源码树 | C | 必读 | 观察头文件 API 组织方式 |

**动手任务**

1. 用 tree-sitter 解析 `.c`/`.h`/`.cpp`，抽取函数与结构体/类节点。
2. 每个代码 chunk 的 metadata：`path`、`symbol`、`kind`、`start_line`、`end_line`。
3. 对抽不到 AST 的文件（或宏很重的）做降级：按空行/头文件声明粗切，并标记 `fallback=true`。
4. 抽样检查：`InitWindow` 这类 API 是否被完整收录。

**验收标准**

- [ ] 对选定库能量产出符号级 chunk 列表。
- [ ] 随机抽 10 个符号，内容完整、路径正确。

**自测题**

1. 为什么代码 RAG 按函数切通常优于按 500 字符切？
2. 只有声明没有实现的头文件，检索时可能有什么问题？
3. 宏与条件编译为什么让 AST 切分变难？

### 周五：检索评测

**学习目标**

1. 建 20 个问题的测试集（含期望来源或期望要点）。
2. 实现评测脚本：召回率、MRR、答案忠实度（规则或 LLM-as-judge 均可，但要记录局限）。

**时间安排**：出题 35 分钟，写脚本 40 分钟，跑评测 15 分钟。

**学习资源**

| 资料 | 语言 | 要求 | 看什么 |
|---|---|---|---|
| [All-in-RAG 评测](https://github.com/datawhalechina/all-in-rag) | 中文 | 必读 | 指标与测试集思路 |
| 你对 raylib API 的了解 / 官方 cheatsheet | 英文 | 必读 | 出题依据 |

**动手任务**

1. 测试集 JSONL 字段建议：`id`、`question`、`expected_symbols` 或 `expected_path_substr`、`answer_key_points`、`type`。
2. 题目覆盖：API 用法、参数含义、概念题、易混函数、跨文件题。
3. 指标：
   - 召回：期望来源是否出现在 Top-K
   - MRR：首个相关来源的排名倒数平均
   - 忠实度：答案是否都有检索依据（可人工+抽检）
4. 对比至少三档配置：纯向量 / 混合 / 混合+重排（有改写可再加一档）。

**验收标准**

- [ ] 20 题测试集落盘。
- [ ] 评测脚本一键输出表格。

**自测题**

1. MRR 和 Recall@K 各强调什么？
2. LLM 当裁判的主要风险是什么？
3. 为什么测试集要版本化，不能每次口头改题？

## 7. 容易踩的坑

- **一上来就 Graph RAG**：本周主线是混合检索+重排+代码切分，图方法只了解。
- **测试集太少或全是简单题**：会误判系统已可用。
- **重排模型过大**：CPU 上会拖垮迭代，换小 reranker。
- **切分后不做抽样**：AST 抽空了也不知道。
- **索引对象选错**：综合项目要用的库尽量本周就选对。
